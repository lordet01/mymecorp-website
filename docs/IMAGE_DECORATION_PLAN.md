# 이모지 → 이미지 전환 계획 (Image Decoration Plan)

## 1. Google 이미지 크롤링을 쓰지 않는 이유

| 항목 | 설명 |
|------|------|
| **저작권** | Google 검색 결과 이미지 대부분은 타인 저작물입니다. 상업용 웹사이트에 무단 사용 시 저작권 침해·민원·소송 위험이 있습니다. |
| **이용약관** | Google은 자동화된 수집(크롤링/스크래핑)을 금지합니다. ToS 위반 시 서비스 제한·법적 조치 가능성이 있습니다. |
| **안정성** | 외부 URL에 의존하면 링크 변경·삭제 시 깨지고, 수집·저장 방식에 따라 법적 리스크가 계속됩니다. |

**결론:** 상업 사이트(myme 법인 등)에는 **라이선스가 명확한 이미지**만 사용하는 것이 안전합니다.

---

## 2. 권장 방향: 무료·상업 이용 가능 이미지 소스

크롤링 대신 아래 중 하나(또는 조합)를 사용하는 것을 권장합니다.

| 소스 | 특징 | 사용 방식 |
|------|------|-----------|
| **Unsplash** | 고품질 무료 사진, 상업 이용 가능 | [Unsplash Source](https://source.unsplash.com/) 또는 [API](https://unsplash.com/developers)로 검색 후 **직접 다운로드 → 프로젝트에 저장** |
| **Pexels** | 무료 사진·영상, 상업 이용 가능 | [Pexels](https://www.pexels.com/)에서 검색 후 **다운로드 → 프로젝트 저장** |
| **Pixabay** | 무료 이미지, 상업 이용 가능 | 웹에서 검색 후 **다운로드 → 프로젝트 저장** |
| **직접 촬영/제작** | 브랜드 일관성 최고 | 스튜디오/제품/UI 스크린샷 등을 촬영·편집 후 저장 |

**원칙:** 이미지는 한 번 다운로드해 `myme_Design Asset`(또는 전용 폴더)에 넣고, **자체 호스팅**하는 방식이 안전하고 안정적입니다.

## 4. 구현 단계 계획

### Phase 1: 이미지 에셋 준비 (수동, 권장)

1. **폴더 구조 정하기**
   - 예: `myme_Design Asset/decor/` 또는 `assets/images/decor/`
   - 용도별: `hero/`, `features/`, `targets/`, `how/` 등으로 구분 가능.

2. **이미지 수집 (크롤링 없이)**
   - Unsplash / Pexels / Pixabay에서 키워드로 검색  
     (예: "business suit", "palette", "smartphone download", "passport", "id card", "selfie profile")
   - 상업 이용 가능·필요 시 모델/재산권 확인.
   - 다운로드 후 **편집(크롭·리사이즈·압축)** 해서 위 권장 해상도에 맞춤.

3. **파일 네이밍 규칙 (예시)**
   - `hero-badge-camera.png`
   - `feature-outfit.png`, `feature-background.png`, `feature-face.png`, `feature-download.png`
   - `target-job.png`, `target-travel.png`, `target-id.png`, `target-profile.png`
   - `how-idea.png` (선택), `icon-lock.svg` (선택)

4. **저장 위치**
   - 모두 `myme_Design Asset`(또는 정한 폴더)에 넣고, 상대 경로로 HTML에서 참조.

### Phase 2: HTML/CSS 수정

1. **기능 카드 (Feature)**
   - `<div class="feature-icon">👔</div>` → `<img class="feature-icon" src="..." alt="..." />`
   - CSS: `.feature-icon`을 이모지용 폰트 크기가 아니라 `width/height`로 제어 (예: 64px).

2. **타깃 섹션 (Perfect for these users)**
   - `<div class="target-emoji">💼</div>` → `<img class="target-emoji" src="..." alt="..." />`
   - CSS: `.target-emoji` 크기 유지 (예: 48px).

3. **히어로 배지**
   - 배지 앞/안에 작은 이미지 넣거나, 배지 배경을 이미지로 처리 (선택).

4. **접근성**
   - 모든 `<img>`에 `alt` 지정.
   - 다국어 페이지면 `data-i18n-alt-key`로 alt도 번역 객체에 넣어 전환 (이미 사용 중인 패턴 활용).

5. **폴백**
   - 이미지 로드 실패 시 이모지나 placeholder가 나오도록 `onerror` 또는 CSS로 처리 가능 (선택).

### Phase 3: 다국어(alt 텍스트) 반영

- `index.html` 내 `copy` 객체에 각 이미지별 alt 키 추가  
  - 예: `"feature.outfit.icon.alt": "Seamless outfit change"` (en) / `"의상 변경"` (ko) 등.
- 해당 `<img>`에 `data-i18n-alt-key="feature.outfit.icon.alt"` 지정 후, 기존 `applyLanguage` 로직으로 alt 갱신.

### Phase 4: (선택) Unsplash API로 “관리자만” 큐레이션

- **크롤링이 아니라** “관리자가 검색 → 고른 이미지를 한 번 다운로드해 저장”하는 반자동화에 활용 가능.
- 로컬/관리자 전용 스크립트에서 Unsplash API로 검색 → URL 목록 출력 → 사람이 선택 → 스크립트가 다운로드해 `myme_Design Asset`에 저장.
- **웹사이트 자체에서는 크롤링하지 않고**, 저장된 파일만 사용.

---

## 5. 체크리스트 요약

- [ ] 이미지 소스는 **Unsplash / Pexels / Pixabay 등 라이선스 명확한 곳**만 사용 (Google 이미지 크롤링 미사용).
- [ ] 모든 이미지 **다운로드 후 프로젝트에 저장**하고 자체 호스팅.
- [ ] 기능/타깃/히어로용 이미지 **해상도·파일명 규칙** 정한 뒤 한 번에 적용.
- [ ] HTML에서 이모지 → `<img>` 교체, CSS로 크기 통일.
- [ ] `alt` 및 필요 시 `data-i18n-alt-key`로 다국어 대응.
- [ ] (선택) 로드 실패 시 이모지 폴백.

이 계획대로 진행하면 이모지를 줄이면서도 저작권·이용약관에 안전하게 이미지로 꾸밀 수 있습니다.  
구체적인 HTML/CSS 수정 예시가 필요하면 “기능 카드부터 이미지로 바꿔줘”처럼 구간을 지정해 주시면 됩니다.
